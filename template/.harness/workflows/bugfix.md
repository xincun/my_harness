# 工作流：修复 Bug（双相红绿与根因治理）

目标：修**根因**而非压症状，先见红（RED）再转绿（GREEN），用消融验证证明改动最小必要。

---

## 阶段 0 · 自由只读分诊（Triage：零形式阻力，不动业务源码）
1. **查历史暗坑**：在 `docs/knowledge/pitfalls.md` 与 `docs/knowledge/bugs/` 搜索报错词，确认是否老问题复发。
2. **只读探查**：自由执行日志检索、进程/端口/配置检查、`codegraph.py callers|callees|node` 调用链追踪。**红线：未完成阶段 1 复现前，严禁修改业务源码。**
3. **用户困惑即隔离警报**：当用户质疑“为什么某个不该出现的数据/行为出现在当前作用域”，立即将其作为【边界隔离失效缺陷】反查过滤契约，禁止仅做表面科普。

## 阶段 1 · 复现探针先见红与契约锁定（动源码的唯一门票）
1. **构造最小外部复现探针（Minimal Reproducer）**：
   - 从真实调用入口（CLI、API 请求、集成测试或顶层公开契约）稳定触发故障；涉及跨进程/OS 服务/网络时，**严禁用纯内存隔离 Mock 微单测充当复现探针**。
   - 涉及白名单、范围过滤或鉴权时，探针同时包含**否定性不变量断言**（非目标实体绝不被误纳入）。
2. **亲眼确认见红（RED）**：运行探针并捕获明确的失败退出码或错误现场（若跑出来是绿的，说明没抓准故障，禁止动源码；确实无法本地复现时向用户说明所需取证信息并 `task.py pause`）。
3. **按规模定档锁定契约**（单点明确根因用 `--tier S`，跨模块/复杂状态用 `--tier M` 或 `L`）：
   ```bash
   python3 .harness/scripts/task.py start --tier M --summary "fix: ..." \
     --accept "C1(先红后绿): <探针命令> 修复前失败，修复后通过" \
     --accept "C2(根因与消融): 根因消除且注释修复行后探针重回失败，无局部特判补丁"
   ```
   > 若用户反馈“上一轮没修好”，严禁沿用上一轮局部单测继续打补丁，必须先重构外部端到端复现探针。

## 阶段 2 · 根因追踪与补丁计数器审查
1. 沿 `codegraph.py callers <符号>` 向上追到**第一处产生错误状态/错误假设**的位置，写出根因句：`<模块#符号> 假设了 <X>，但在 <Y> 下不成立`。
2. **补丁计数器检查（Rule of Two Patches）**：
   - 用 `git log -S` 或读上下文检查该处是否已有针对同类漏判/误判的白名单、正则例外或启发式分支。
   - **若已是第 2 次需要追加特判**：立即停下向用户报告“这是机制选型缺陷”，给出结构性替换方案，**严禁打第 3 个补丁**。
   - 禁止症状式掩盖（吞异常、盲加 `sleep`/重试、改松测试断言）。

## 阶段 3 · 根因修复、消融检验与同类排查
1. **最小结构性修复**：在根因处修正假设；涉及异步/资源释放时对照 [architecture_principles.md](../../docs/guidelines/architecture_principles.md) 检查回调时序与排空态（Drain）。
2. **消融反向验证（Ablation Check）**：修复转绿后，临时注释/回退核心修复行重跑探针——**必须立刻重新变红**（若仍为绿说明修在了无效分支，当场删掉重定位），确认后恢复修复代码。
3. **爆炸半径与同类排查**：运行 `codegraph.py impact <被修符号>` 确认调用方兼容；在仓内搜索相同错误假设（少量确定的一并修复，范围大的在汇报中列出）。

## 阶段 4 · 沉淀判断与唯一单步闭环
1. **按需沉淀**：常规简单 Bug 写清提交信息即可（`--learned none`）；若根因与症状跨层分离、排查极其隐蔽或有复发风险，按 [learn.md](learn.md) 更新 `pitfalls.md`（已存在则 `命中 +1`）或用 `.harness/templates/bug.md` 记录到 `docs/knowledge/bugs/`。
2. **运行唯一一次 `task.py finish`**（一步完成全量 `verify.py`、`kb_check.py` 与指标记录）：
   ```bash
   python3 .harness/scripts/task.py finish --type bugfix \
     --covers "C1=<探针先红后绿输出>" --covers "C2=<根因位置与消融重红确认>" \
     --friction "none 或排查阻碍" --learned "none 或 pitfalls#P..."
   ```

## 汇报模板
```markdown
## 已修复：<bug 一句话>
- **根因**：`<path#符号>` 假设了 X，在 Y 下不成立
- **修复与消融**：`path#符号` — 改动说明（已验证回退该处探针重回 RED）
- **双相验证**：探针命令（RED 报错摘要 → GREEN 通过摘要）+ `verify.py` 全绿
- **同类排查与残余风险**：…
- **知识沉淀**：`pitfalls#P...` / `bugs/...`（或“无，见提交信息”）
```
